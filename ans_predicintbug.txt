| Volatile Keyword vs Hardware Memory Fences (LKML 2007 Debate)                         |
| Memory Locations: [0x500] = payload | [0x508] = ready_flag                            |
+---------------------------------------------------------------------------------------+
code: volatile int ready_flag = 0; uint64_t payload = 0;
Producer CPU₀: payload = 0xDEADBEEF; ready_flag = 1;
Compiler generated assembly without store fence:
movq $0xDEADBEEF, 0x500
movl $1, 0x508
Hardware execution: CPU₀ store buffer holds 0x500 (delayed due to cache miss on 0x500); 0x508 hits L1 cache → 0x508 drains first!
Consumer CPU₁: while (!ready_flag); result = payload;
CPU₁ sees: ready_flag = 1 at time 20ns → reads payload at 0x500 at time 22ns
CPU₁ reads 0x500 = 0x00000000 (payload store not yet committed from CPU₀ store buffer)
result: payload = 0x00000000 ≠ 0xDEADBEEF ✗
Axiom: `volatile` keyword guarantees compiler will not elide read/write; `volatile` gives ZERO hardware ordering guarantee
Required atomic operations with memory orders:
Producer: __atomic_store_n(&payload, 0xDEADBEEF, __ATOMIC_RELAXED); __atomic_store_n(&ready_flag, 1, __ATOMIC_RELEASE);
Consumer: while (__atomic_load_n(&ready_flag, __ATOMIC_ACQUIRE) == 0); result = __atomic_load_n(&payload, __ATOMIC_RELAXED);
Hardware emits Release store fence → payload visible before ready_flag ✓

F01: False sharing of head and tail in same 64B cache line
- breaks: addr(head)=0x100, addr(tail)=0x104 -> same cache line 0x100..0x13F
- expected: L1 write latency = 4 cycles = 1.33ns
- actual: MESI ping-pong RFO bus invalidations = 120 cycles = 40ns per access
- ✗ expected 1.33ns -> actual 40.0ns (30x latency degradation)

F02: Missing write memory barrier in lockless SPSC queue
- breaks: out-of-order store buffer drains store(head) before store(data)
- expected: consumer reads valid payload 0xCAFEBABE
- actual: consumer reads uncommitted stale memory 0x00000000
- ✗ expected 0xCAFEBABE -> actual 0x00000000 (silent data corruption)

F03: Non-power-of-two ring buffer index wrap
- breaks: 4294967295 mod 1000 = 295 -> overflow to 0 mod 1000 = 0
- expected: slot transition 295 -> 296
- actual: slot transition 295 -> 0 (296 slots skipped)
- ✗ expected 296 -> actual 0 (ring buffer desynchronization)

F04: Bitmasking with non-power-of-two modulus
- breaks: counter & (1000 - 1) = counter & 999 where 999 = 0b001111100111
- expected: counter=8 maps to slot 8
- actual: 8 & 999 = 0 (maps to slot 0, colliding with counter=0)
- ✗ expected slot 8 -> actual slot 0 (queue overwrite collision)
